# 服事表圖片轉 JSON 的 prompt（模板）

**這是模板，不要直接用。** 裡面的 `{{...}}` 要由
`scripts/build-import-prompt.py` 從 Firestore 填進去，產生的成品會寫到
`.local/`（已 gitignore）。

這個 repo 是公開的，所以同工姓名、綽號對照一律不寫在這裡。
下面範例裡的人名都是虛構的。

## 怎麼用

服事表的照片轉 JSON 是在 claude.ai 上做的（手機也能用）。這個 repo 只負責
產生那份技能，並在需要時驗證產出的 JSON。

```
python3 scripts/build-claude-skill.py
```

從 Firestore 抓現況，產生 `.local/claude-skill/roster-import.zip`，
上傳到 claude.ai 的技能設定。之後在 claude.ai 附上服事表照片說「轉 json」，
把結果貼進 app 匯入即可。

**名單有異動時**重跑這支再上傳覆蓋。忘了也不會壞，見下一節。

匯入前想先確認的話（人在這台機器前時）：

```
python3 scripts/preview-roster-import.py <崇拜類別> <json 檔>
```

這支會抓 Firestore 現況、產生一支暫時的 Dart 測試去呼叫 app 真正在用的
`parseRosterImportJson`，印出按下匯入會看到的結果 —— 哪些名字對不上、
哪幾天不在範圍內、每天的項目排序。跑完自動刪掉那支測試。

## 為什麼要把名單填進 prompt

app 的姓名比對**沒有模糊比對**：先找一模一樣的，找不到就找「名單裡以這個
字串結尾、而且只有一個人符合」的。兩條都是精確比對，**錯一個字就是查無此人**。

中文名字常有罕用字，而那正是 OCR 最容易認錯的地方。辨識成形近字之後，
那個人就會落進「名單裡沒有這個人」，也收不到服事提醒。

所以 prompt 裡附上完整名單當白名單，讓模型只能從裡面挑，不要它自己拼字。

**忘了重新產生也不會壞** —— 新同工不在名單裡時，LLM 會照表格原文輸出，
app 那邊的後綴比對照樣接得住（只要 OCR 沒把字認錯）。認錯的話那個人會出現
在匯入結果的「名單裡沒有這個人」。名單過期只會讓**新來的那幾位**退回舊模式。

## 模板本文

````
幫我把服事表照片轉成 JSON。只輸出 JSON，不要有任何說明文字，
不要用 markdown 的程式碼圍欄包起來。第一個字元是 [，最後一個字元是 ]。

## 只要這些

日期、服事項目、同工、活動。其他一律不要。

## 服事項目命名

只能用以下名稱，一字不差：
{{ROLES}}

清單裡沒有的欄位整欄不要輸出。
{{EXTRA_ROLE_RULES}}

## 人名

**輸出的人名必須是下面同工名單裡的其中一個全名，一字不差。**
表格上寫的是簡稱（去掉姓氏）或加了稱謂，你要把它還原成名單裡的全名。

同工名單：

{{NAMES}}

規則：

- 表格上的「小明」「小明哥」「陳小明」都要輸出成「陳小明」。
  稱謂是哥／姐／姊／兄／弟／妹。
- 中文名字有很多罕用字，照片上可能看不清楚或容易認錯。
  **不要自己拼字** —— 從名單裡挑字形最接近的那一個。
- 一格有多個人就拆成多個元素。表格用「/」或「+」分隔的都算多人，
  例如「小明/大華」→ ["陳小明", "林大華"]。
- 空白格代表這一項還沒排到人 → "people": ["待定"]。「待定」照寫，不用對名單。
- 「暫停」不是人名，代表那週沒有這一項 → 整個項目不要輸出，
  不可以寫成 ["暫停"]。
- 真的對不到名單裡任何一位（例如新同工還沒建帳號），就照表格原文輸出，
  不要硬塞一個名單裡的人。
{{NICKNAMES}}
{{TEAM_RULES}}
## 活動

放進該天的 `events`。以下都算活動：

- 表格右側時段欄位裡的內容（欄名只是時段，那些活動就在**同一天**，不是別天）。
- 橫跨多欄的合併儲存格。

規則：

- 意思相同的話，優先用下面這幾個既有名稱，一字不差：
  {{EVENTS}}
- 對不到既有名稱的就照表格原文一整串抄，**不要拆**。
  合併儲存格裡的「活動名稱/地點」是一個名稱，那個「/」不是分隔多人的意思。
- 同一天有多個活動就放多個元素；同一天不可以有重複的活動名稱。
- **不要輸出顏色。**
- 那一天沒有任何活動的話，**整個 `events` 欄位不要寫**（不要輸出 `[]`）。

## 橫跨多欄的合併儲存格

那代表那週的常規服事被活動取代 → 被蓋到的那些服事項目**都不要輸出**，
只輸出活動。沒被蓋到的欄位照常輸出。

## 不要輸出的欄位

- 格子裡自己寫了另一個日期的欄位（例如「週二禱告會」那種），
  跟這一列的日期不同天，整欄略過。
- 表格下方的提醒、標題、經文、季主題。

## 格式

[
  {
    "date": "2026-07-04",
    "duties": [
      {"role": "{{SAMPLE_ROLE_A}}", "people": ["陳小明"]}
    ],
    "events": ["夏令營/營地"]
  },
  {
    "date": "2026-07-11",
    "duties": [
      {"role": "{{SAMPLE_ROLE_A}}", "people": ["陳小明", "林大華"]},
      {"role": "{{SAMPLE_ROLE_B}}", "people": ["待定"]}
    ]
  }
]

- `date` 一定是 `YYYY-MM-DD`。不可以寫 `2026/07/11` 或 `7/11`。
  年份從表格標題推斷（例如標題寫「2026 年 7-9 月份」）。
- `people` 的每個元素都必須是字串。不可以出現 null、數字。
- `duties` 不可以是空陣列。那天完全沒有服事就不要寫 `duties` 這個欄位。
- 每一天至少要有 `duties` 或 `events` 其中一個，兩個都沒有就整天不要輸出。
- 同一個日期只能出現一次。
- duties 的排列順序不重要，匯入後會自動照服事項目設定重排。

## 輸出前自我檢查

1. 每個 date 都是 YYYY-MM-DD，而且沒有重複。
2. 每個 role 都在上面的命名清單裡，一字不差。
3. people 裡的每個名字都在同工名單裡找得到一模一樣的，或是「待定」。
   沒有 null、沒有數字、沒有「暫停」、沒有哥姐。
4. 沒有空的 duties 陣列、沒有空的 events 陣列。
5. 同一天的 events 沒有重複的名稱。
6. 輸出的第一個字元是 [，最後一個字元是 ]，前後沒有其他文字。
````

## 各崇拜的差異怎麼設定

服事項目與活動清單由腳本從 Firestore 的 `settings/roster_templates`、
`settings/event_options` 讀出來填入，不必手動維護。

只有下面兩段是各教會自己的規則，放在 `.local/import-rules.json`：

```json
{
  "youth": {
    "extraRoleRules": "- 表格的「會前禱+奉獻」是一欄，要拆成兩項：會前禱告、奉獻教導。\n  同一格的人兩項都填。",
    "teamRules": "## 敬拜團\n\n敬拜團那一欄寫的是團名，實際人員在表格下方的說明列。..."
  }
}
```

沒有這個檔案的話那兩段就留空，其餘照常產生。

---

## 活動顏色

prompt 刻意不輸出顏色。顏色設在 app 的「事件選項設定」，名稱一樣就會自動套用。

不在事件設定裡的活動還是會標上去，只是沒有預設色，並列在匯入結果的
「活動沒有固定顏色」。常出現的活動建議加進事件設定。

## 匯入後會看到什麼

app 匯入完會跳出「匯入結果」。裡面列的名字**都已經寫進服事表了**，
列出來是讓你知道，不是要你回去改 JSON：

- **沒有設定這個服事** — 人在名單上，只是沒設定這一項（臨時支援很正常）。
  真的多了固定班底才需要按「新增服事至同工」。
- **名單裡沒有這個人** — 名字有排上去，但沒有帳號就收不到服事提醒。
  看到綽號出現在這裡，就把它加進 `.local/import-rules.json` 的綽號對照。
- **不確定是哪一位** — 名單裡有兩個人的名字都對得上，這一格沒有連到帳號。
- **這幾天沒有匯入** — 服事表裡沒有那幾天。app 只產生本季與下季。
- **活動沒有固定顏色** — 活動標上去了，只是沒有預設色。
