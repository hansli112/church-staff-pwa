# 介面設計原則

> 依據 Apple Human Interface Guidelines。審查畫面時用 `apple-design` skill（[dickwu/apple-design-skill](https://github.com/dickwu/apple-design-skill)，裝在本機 `~/.claude/skills/`，不放進 repo），引用時寫 `檔名 › 標題`。

一句話：**同工打開 App 是為了看自己哪天服事、或把服事表排完。其他東西都要讓路。**

## 少操作

- 一個畫面一個主要動作，用醒目樣式；次要動作收進選單。例外：登入頁的 Google 和 Apple 登入不用強調色，照兩家的品牌規範都用白底細框加自己的標誌（Google 一定要彩色 G，Apple 不能比其他登入按鈕小），一樣大；iPhone 上 Apple 在前，Android 和網頁 Google 在前。
- 能用預設值就不要問。新的服事表帶入上次的服事項目；選人時照同工排序排好。
- 給選項，不要人打字。必須打字時用對的鍵盤類型、即時驗證。
- 選日期、時間像 iPhone：日期是月曆，點一天就選好，不用再按確定（不用 Material 的日期、時間對話框）；時間用滾輪。開選擇器或底部視窗前先收鍵盤，關掉後也不再跳回來；鍵盤開著時，底部視窗的清單要捲得出鍵盤。
- **用復原取代確認**。一般刪除、移除後顯示「已刪除 · 復原」提示。只有自己無法復原的動作才跳確認視窗，並附「取消」：退出教會、刪除帳號、刪除教會。另一種是 sheet 裡改了還沒按「完成」就要關掉（滑下、點外面、返回、「取消」）：照 Apple HIG〈Sheets〉問「放棄變更？」，取消那顆寫「繼續編輯」，因為放棄的東西沒有復原可按；iPhone 上從下面出來（動作選單），Android 用對話框。
- 不在啟動時跳任何視窗。權限（推播）在第一次用到時才問，並說明用途。唯一的例外是教會專屬 icon 自動換上時 iOS 系統自己的提示：每支手機一次，等教會頁面出來才換，App 同時說明並給「復原」。

## 少文字

- 不放說明段落。需要解釋才看得懂的畫面，先改畫面。
- 空白狀態只放一句話加一顆按鈕，直接邀請下一步。分頁整頁空白時，上面加一個大圖示（中性色）。
  - 反例（self-host 選人視窗）：「還沒有同工可排『司琴』。請到『我的』→『帳號管理』編輯同工，勾選『司琴』，他就會出現在這裡。」
  - 改成：「還沒有人負責司琴」＋按鈕「新增同工」。
- 按鈕寫會發生什麼事：「儲存」「退出教會」，不寫「確定」「送出」。同一個動作從頭到尾用同一個詞。
- 錯誤訊息說怎麼修，不道歉、不講技術原因。
- 句尾句號：只有一句的不加（按鈕、標籤、一句話的提示和說明都不加），兩句以上才加，而且每句都加。五種語言都照這個規則。
- 用詞照 `CONTEXT.md`。

## 乾淨的畫面

- 中文用系統字型。Android 的英數改用內建的 Martha Latin（Source Sans 3 放大到思源黑體的英數大小），Roboto 在中文旁邊顯得太小太細；iOS、網頁照用系統字。內文 17pt，最小 11pt；用字重與大小分層級，不靠顏色。
- 以 8pt 為單位排版；少用框線與卡片陰影，靠留白分組。
- 顏色：中性色加一個強調色，強調色只用在主要動作與狀態（今天的日期方塊也是狀態）。一個顏色只代表一件事。列左邊的 icon、分段按鈕選中的那塊用中性色；服事表上自己的名字用粗體，不用強調色。
- 例外：「設定」的列，icon 放在彩色圓角方塊上（像 iPhone 的設定），同一種列同一個顏色（`TileColors`：管理教會、我的教會、支持、LINE、其他；刪除帳號用紅色，和它的紅字同一個意思），長的頁面一眼分得出組。其他頁面不用彩色方塊。
- 圖示：整個 App 只用 Material Symbols 圓角款。例外：Apple 登入的標誌；Flutter 元件自帶的（返回鍵、展開箭頭、下拉箭頭）照預設，只有網頁版的返回鍵照手機改：Flutter 在網頁一律畫 Android 的 ←，iPhone、iPad 上的網頁版改成和 App 一樣的 ‹。列裡用空心；實心只給選中的分頁、狀態（勾選）、搜尋框的清除鈕，和彩色方塊裡的白色圖示（空心的白線太細）。服事項目不配圖示，那是各教會自己取的名字。
- 頭像：名字的第一個字放在中性色的圓裡，跟著字級放大。
- 日期：服事和活動的列、服事表的卡片，左邊放日期方塊（月份小、日期大，今天用強調色），旁邊寫星期幾和「今天」「明天」，不是今年再加年份；方塊報讀日期，旁邊的字報讀其他的，不重複。已經開始還沒結束的活動算今天。
- 淺色、深色都要支援，跟著系統走，不做 App 內的外觀開關。
- 教會 logo 只出現在固定位置（頂部、歡迎畫面），不重複出現。

## 好用的基本功

- 點擊範圍至少 44×44pt（Android 48dp）。
- 文字跟著系統字級放大，最大字級下版面不壞。
- 文字對比：17pt 以下 4.5:1，18pt 以上或粗體 3:1。
- 不只用顏色傳達意思；只有 icon 的按鈕要有無障礙標籤。
- 動畫短、可中斷，常用操作不加動畫；尊重「減少動態效果」。
- 載入時先顯示快取資料，不擋住畫面；不用全畫面轉圈。行事曆和平台後台的資料每次都要向伺服器要，先顯示這台裝置上次讀到的，同時重新讀；這台裝置還沒讀過時，轉圈放在內容區中間。

## 跨平台

三個平台用同一套外觀（自己的元件庫），以下依各平台習慣：

| 元件 | 做法 |
| --- | --- |
| 頂層導覽 | 底部分頁列，最多 4 個，單字標籤 |
| 返回 | iOS 從左緣滑動返回；Android 系統返回鍵（預測返回）。不鎖返回：離開前要問的事，改在回到的那頁用提示給按鈕。Android 在其他分頁的最上層按返回，先回「首頁」，再按才離開 App |
| 底部面板 | 有拉桿、可下滑關閉；最高到畫面的 92%，上面露出後面那頁。有表單或要按「完成」的，上面一列左「取消」、中間標題、右「完成」或「儲存」（`SheetBar`），改過就先問再關。一次一張，不在 sheet 上疊 sheet，選項在原地展開 |
| 中間的視窗 | 只給無法復原的確認和一兩個字就答得出的問題；跟著某個動作的幾個選項用底部面板 |
| 確認視窗、輸入文字的視窗、開關 | 用平台樣式（Flutter 的 `.adaptive` 元件；輸入文字在 iPhone 是 Apple 的 alert 加文字欄） |
| 左滑刪除 | 紅底上寫「刪除」（`SwipeDeleteBackground`），只有紅色看不出放手會怎樣 |
| 觸覺回饋 | iOS、Android 都加在完成、刪除這類關鍵動作 |

## 審查

- 每個新畫面上線前用 `apple-design` skill 審一次，Critical 與 High 的問題要先修。
- 審查時問一次：這個畫面有什麼可以拿掉？
